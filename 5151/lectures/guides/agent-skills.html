Paper Guide · Week 3 — Tools, MCP & Evaluation

Equipping Agents for the Real World with Agent Skills

MCP standardizes how an agent calls a tool. Agent Skills standardizes how an agent picks up domain expertise — folders of instructions, scripts and resources it loads only when a task actually needs them.

Read the paper ↗ Zhang, Lazuka & Murag (Anthropic) · October 2025 ← Back to Tools, MCP & Evaluation
01 · In plain terms

You can't pre-load every specialist manual into the prompt

A general-purpose agent could, in principle, be handed hundreds of specialized procedures — how to format a company's spreadsheets a particular way, how to follow a specific brand's style guide, how to file a specific kind of report. Pasting all of that into the system prompt up front doesn't work: it burns context budget on instructions for tasks the user isn't doing right now, and — per Week 3's own "lost in the middle" finding — stuffing more into the context window doesn't mean the model reliably uses all of it. Agent Skills is Anthropic's answer: package each piece of expertise as its own small directory, and reveal it to the model in stages, so the cost of "knowing about" a skill is tiny until the moment the model actually needs to use it.

02 · How it works

Progressive disclosure, in three tiers

A Skill is a directory containing a SKILL.md file: YAML frontmatter with two required fields — name (max 64 characters, lowercase/numbers/hyphens only) and description (max 1024 characters) — followed by the skill's actual instructions in the file body, plus optionally scripts and reference files alongside it. What makes this scale to dozens of skills without flooding the context window is that none of it loads at once:

  • Level 1 — metadata, always loaded. Just the name and description for every installed skill, sitting in context the whole session. Anthropic reports a median cost of ≈80 tokens per skill at this tier — this is the only information the model has to decide whether a skill is relevant, which is why a precise, specific description matters more than anything else in the file.
  • Level 2 — full instructions, loaded on trigger. Once the model judges a skill relevant to the current task, it reads the rest of SKILL.md — ranging from ~275 to ~8,000 tokens across Anthropic's own published skills, median around 2,000.
  • Level 3 — reference files and scripts, loaded on demand. Anything else in the skill's directory (a detailed style guide, a helper script) is read only at the point of actually executing a step that needs it, never speculatively.

Skills and MCP are complementary, not competing: MCP standardizes the mechanics of a tool call (a schema, an execution, a result); a Skill's instructions are free to tell the agent which MCP tool to call and how, for this specific specialized task.

04 · For your talk & project

What this buys you

  • If you present S1-2 Tool Use & MCP or S1-3 Agent Memory: Agent Skills is CoALA's procedural memory turned into a concrete, portable file format — frame it that way and the connection to the rest of the seminar program becomes obvious.
  • For your project's architecture (R1, R2): if your agent needs several distinct specialized behaviors, packaging each as a Skill-style directory (even without using Anthropic's exact format) is a cleaner design than one giant system prompt — and it's a concrete answer to "how does your design avoid the lost-in-the-middle problem?" in Q&A.
  • A sharp critical question to raise: since only the name/description decide whether a skill loads at all, what happens when two skills have similar-sounding descriptions — how would you debug the agent picking the wrong one?
