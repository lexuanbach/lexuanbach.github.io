Paper Guide · Week 1 — Introduction & Methodology

ReAct: Synergizing Reasoning and Acting

The paper that gave the field its default agent loop — Thought, Action, Observation, repeat — and the one Week 1's simulator and DAG critique both build around.

Read the paper ↗ Yao, Zhao, Yu, Du, Shafran, Narasimhan & Cao · ICLR 2023 ← Back to Introduction & Methodology
01 · In plain terms

Think a little, act, look at what happened, repeat

Before ReAct, researchers had two separate tricks: chain-of-thought prompting (make the model "think out loud" before answering) and action-taking agents (have the model call tools, with no visible reasoning). ReAct's insight was to interleave them explicitly, in the model's own output: write a Thought, take an Action based on it, read the Observation the action produced, then write the next Thought — now informed by what actually happened, not just what the model assumed would happen. That interleaving is the reason ReAct traces read like a person thinking out loud while using a search engine, and it's the exact loop Week 1's interactive simulator plays out step by step.

02 · How it works

The Thought → Action → Observation loop

Mechanically, ReAct is just a prompting pattern (no fine-tuning required, unlike Toolformer): the prompt shows a few examples of the Thought/Action/Observation format, then the model continues it for the real task. Each Action is a structured call (e.g. Search[query], Lookup[string], Finish[answer]) that a wrapper program parses, executes against a real API or environment, and feeds back as the next Observation — the model never actually touches the API itself. The loop terminates when the model emits a terminal action like Finish[...].

The paper evaluated this on four very different benchmarks — HotpotQA and Fever (knowledge question-answering and fact-checking, backed by a Wikipedia search API), ALFWorld (a text-based embodied environment) and WebShop (webpage navigation) — precisely to show the pattern generalizes across "look something up" and "act in a world" tasks, not just one benchmark. On HotpotQA, interleaving reasoning with retrieval measurably reduced the hallucination and error-propagation ReAct's ablation (chain-of-thought with no tools at all) suffered from; on ALFWorld, ReAct beat imitation- and reinforcement-learning baselines by an absolute 34-point success-rate margin using only 1–2 in-context examples — no task-specific training at all.

Worked exampleThe exact trace from Week 1's simulator

Task: "Who directed the film that won Best Picture at the 2023 Oscars?" — run with the react scenario in the Week 1 simulator:

Thought 1I need to find out who directed the film that won Best Picture in 2023. Action 1Search["2023 Best Picture Oscar winner"] Observation 1"Everything Everywhere All at Once" won Best Picture at the 95th Academy Awards. Thought 2Now I need to find the director(s) of that film. Action 2Search["Everything Everywhere All at Once director"] Observation 2Directed by Daniel Kwan and Daniel Scheinert. Thought 3I have the answer. Action 3Finish["Daniel Kwan and Daniel Scheinert"]

Compare this against the simulator's no-tools scenario on the same task — the model has to guess from parametric memory alone, with no Observation to correct it. That contrast is the entire argument of the paper in one screen.

04 · For your talk & project

What this buys you

  • If you present S1-1 Advanced Reasoning & Planning: ReAct is the baseline every later technique in that topic (Reflexion, ToT, LATS) is a modification of — say explicitly what each later paper adds to this loop, which is exactly the "must explain" checklist's ask.
  • Week 1's §5 critique already argues ReAct assumes actions are cheap and reversible — bring a concrete counter-example from your own project domain (an action that is expensive or irreversible) to Q&A.
  • For your project architecture (R1): if your system uses a ReAct-style loop, say so explicitly and cite this paper — reviewers will assume ReAct by default unless you name a different control-flow pattern.
